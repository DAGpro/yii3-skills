## Yii3 support (from yii3-skills)

Load the `yii3` skill and verify per its "Finale — Definition of Done" — the skill is the single source of gates:

Operating context: this `aif-*` workflow runs the skill in its default AI Factory extension mode (contract: `references/core-aif-adapter.md`); the standalone fallback contract (`references/core-standalone-adapter.md`) is out of scope here.

Verify-specific duties (the rules themselves live in the skill; all `references/*.md` paths resolve relative to the `yii3` skill directory):
- Code-Read-Only invariant (Step 0): this workflow is strictly an independent verification gate — never modify application code (`src/`, `config/`, `migrations/`); report all defects as blockers for `/aif-fix`.
- Project build, packages & version audit (Step 2): run static analysis & linters per project setup (Psalm/PHPStan, Rector, PHP-CS-Fixer); unknown classes, missing `declare(strict_types=1);`, or leftover legacy APIs audited against `references/core-version-notes.md` (R1–R24) via `composer.lock` are blocking; packages used in code must be declared in `composer.json` (`references/package-catalog.md` §5); enforce "Pick Exactly ONE per Family" (§3: PHPUnit xor Testo, AR xor Cycle). If `vendor/` is missing offline, set tests to `not run` and unverified APIs to advisory warnings (`status: "warn"`), never blocking unless syntax fails.
- Chain Integrity & compliance audit (Step 3, Finale item 2, blocking): verify DI bindings for new interfaces (never inject `ContainerInterface`), active routes for actions, console/event/RBAC wiring, reversible migrations (`down()` in `RevertibleMigrationInterface`), and post-commit event dispatch. Audit modified files against the Anti-Pattern Matrix of their governing guides in `references/` (thin actions, atomic use cases, isolated repositories, DTO validator attributes, PSR-15 order); nothing edited in `vendor/` or `config/.merge-plan.php`.
- Architecture pattern & DoD audit (Step 3): evaluate against `references/core-definition-of-done.md` (Multi-Dimensional Quality Evaluation Matrix; for worker runtimes, verify `StateResetter` registration per `references/infra-state-resetter.md`). File-placement judgments consult `references/core-architecture-alignment.md`: dependency-rule violations (SQL in actions, cross-context direct DB access/internal entity imports, domain logic dumped in `Main`) → blocking, convention-only mismatches (layout, naming) → `WARN [architecture-drift]` (never rewritten per the skill's Core rule 2).
- Zero-ambiguity gate result & handoff (Step 4 & Step 5): append the final machine-readable fenced block with language `aif-gate-result` per the AI Factory 2.x contract (`schema_version: 1`, `gate: "verify"`, `status: "pass" | "warn" | "fail"`, `blocking: boolean`, `blockers: [{ id, severity: "error" | "warning", file?, summary }]`, `affected_files`, `suggested_next: { command: "/aif-commit" | "/aif-fix" | "/aif-rules" | "/aif-architecture" | "/aif-roadmap" | null, reason }`). Strictly separate the evaluated perimeter (`affected_files`) from defect files (`blockers[].file`). Update the plan's `### Execution State` (`Status: COMPLETE` when blockers is empty, else `BLOCKED` with explicit entries under `Open Issues` and `Next Stage: /aif-fix`) per the AI Factory Adapter contract (`references/core-aif-adapter.md` §3).
