# Yii3 conventions

> Layout below is only a fallback. The architecture artifact or the project's real structure wins — see `architecture-alignment.md`.

## Layout (typical `yiisoft/app` / `yiisoft/app-api` template — always verify against the actual project)
```
config/
  common/      di/*.php, params.php, routes.php, bootstrap.php, aliases.php
  web/         di/*.php, params.php, events.php
  console/     commands, params
  environments/{dev,test,prod}/
  .merge-plan.php          # generated by yiisoft/config — never edit
src/           # application code (feature-oriented in the newer templates)
public/index.php
yii            # console entrypoint
tests/  runtime/
```
Autoload: PSR-4 from `composer.json`. Config groups are declared in `composer.json` → `extra.config-plugin`.

## Config
- Config files `return` arrays; `$params` is available inside config files.
- DI: `config/common/di/*.php` → `[Interface::class => Implementation::class]` or definition arrays (`'class'`, `'__construct()'`, `'setX()'`).
- Package params live under the package name key (e.g. `$params['yiisoft/view']`); override in project params.
- Environment-specific differences go to `config/environments/*` or `params-local.php` — not into code.

## Code
- `declare(strict_types=1);` everywhere. Prefer `final` classes, `readonly` properties, typed everything.
- Constructor injection of interfaces (PSR / package interfaces). No `new` for services, no service locator, no `Yii::$app`.
- **Actions / handlers:** an invokable class or a PSR-15 request handler taking `ServerRequestInterface` and returning
  `ResponseInterface`. Match how existing actions in the project are written (single-action classes vs controllers).
- **Routes:** declared in the routes config (`Route::get('/path')->action(Action::class)->name('name')`, groups, middleware) —
  check the project and the installed `yiisoft/router` version for attribute routing support before using it.
- **Input:** map the request to a DTO/input class (hydrator / input-http) and validate with `yiisoft/validator` rules,
  rather than reading raw request arrays all over.
- **Responses:** JSON via `yiisoft/data-response`; HTML via the view renderer. No `echo`/`die`.
- **DB:** use `ConnectionInterface` from `yiisoft/db`; migrations via `yiisoft/db-migration`. If the project uses ActiveRecord or
  Cycle, follow it — do not mix ORMs.
- **Events/logging:** PSR-14 `EventDispatcherInterface`, PSR-3 `LoggerInterface`.
- **Console commands:** Symfony Console commands registered through params of `yiisoft/yii-console`.

## Anti-Patterns & Yii2 Migration Matrix (STRICTLY PROHIBITED)

| Forbidden Yii2 Anti-Pattern | Required Yii3 Idiom |
|---|---|
| ❌ `Yii::$app->...` | ✅ Constructor injection of PSR/Yiisoft interfaces via DI. |
| ❌ `class SiteController extends Controller` with `actionX()` | ✅ Single-Action invokable classes: `__invoke(ServerRequestInterface $request): ResponseInterface`. |
| ❌ `$this->render('index', [...])` | ✅ Inject `Yiisoft\Yii\View\Renderer\ViewRenderer` and call `$this->viewRenderer->render(...)`. |
| ❌ `$request->post('name')` / `$request->get('id')` | ✅ PSR-7 `$request->getParsedBody()`, `$request->getQueryParams()`, or `CurrentRoute::getArgument('id')`. |
| ❌ `ActiveForm::begin()` in templates | ✅ `Yiisoft\Form\Widget\Form::widget()->action(...)->open()` and `Yiisoft\Form\Widget\Field`. |
| ❌ `rules()` and `behaviors()` on ActiveRecord models | ✅ Validation attributes `#[Rule]` on DTOs via `yiisoft/validator`; behaviors replaced by PSR-14 events. |
| ❌ `Url::to(['/route', 'id' => 1])` | ✅ Inject `Yiisoft\Router\UrlGeneratorInterface` and `$urlGenerator->generate('route', ['id' => 1])`. |
| ❌ `Yii::$app->user->identity` / `id` | ✅ Inject `Yiisoft\User\CurrentUser` and call `$currentUser->getIdentity()`. |
| ❌ Editing `vendor/` or `config/.merge-plan.php` | ✅ Always configure via `config/**/params.php` or `config/**/di/*.php`. |
| ❌ Guessing method signatures | ✅ Always inspect `vendor/yiisoft/<pkg>/src/` or `references/<pkg>/src/` first. |
| ❌ Creating a second competing mechanism (second ORM, router, DI style) | ✅ Adhere strictly to the detected project stack. |

## Verification
Use the project's commands (composer scripts / Makefile / Docker): phpunit, psalm/phpstan, php-cs-fixer/ecs, rector (if configured).
