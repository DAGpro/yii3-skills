# Yii3 Production Audit: Security & Performance

Checklist-based skill for auditing and hardening a Yii3 application before release.

## Part A: Security

### Trusted Proxies

Behind a reverse proxy / load balancer, user IP and protocol arrive in headers. Do NOT blindly trust
them from anyone — configure trusted hosts via `TrustedHostsNetworkResolver` middleware:

```php
$resolver = $resolver->withAddedTrustedHosts(['10.0.2.0/24']);
// custom headers:
$resolver->withAddedTrustedHosts(['10.0.2.0/24'], ['X-ProxyUser-Ip'], ['Front-End-Https']);
```

Add the middleware near the top of the stack; restrict CIDR lists to actual infrastructure.

### CSRF

1. `CsrfTokenMiddleware` must run before routing for web contexts (check stack order).
2. `CsrfViewInjection` present in `'yiisoft/yii-view' => ['injections' => [...]]`.
3. Every mutating form passes `->csrf($csrf)`; SPA/API clients send the token header
   (`CsrfHeaderMiddleware`).
4. State-changing endpoints never accept GET.

### Session & Cookie Flags

- Session cookie: `HttpOnly=true`, `Secure=true` (HTTPS), `SameSite=Lax|Strict`.
- Options via `$params['session']['options']` in DI; sign/encrypt tamper-sensitive cookies.
- High-concurrency apps move sessions to Redis/Memcached handler (default file storage locks).

### Output & Injection Audit

- All template output escaped with `Html::encode()`; raw HTML only from trusted sources.
- DB access uses parameter binding — grep for string-concatenated SQL.
- Uploaded files validated server-side (`/yii3-forms`, "File Uploads"), stored outside public root,
  names generated by the app.
- No secrets in committed code/config — env vars only.

### Security Headers

| Header                            | Recommendation                    |
|-----------------------------------|-----------------------------------|
| `Strict-Transport-Security`       | enable once HTTPS is permanent    |
| `X-Content-Type-Options: nosniff` | always                            |
| `Content-Security-Policy`         | restrict script/style sources     |
| `Referrer-Policy`                 | `strict-origin-when-cross-origin` |

Add via an application-wide middleware that post-processes the response (middleware Pattern C).

### Error Exposure & AuthZ

- Debug mode off in production (`Environment::appDebug()`); generic messages in production
  renderers (`/yii3-errors`) — no stack traces, paths, or SQL in responses.
- Passwords hashed via `yiisoft/security` `PasswordHasher` (argon2); protected routes wrapped with
  `Authentication` middleware (`yii3-auth`); RBAC checks in services/actions, not templates.

### Dependencies

`composer audit` passes; no known CVEs; autoload optimized (`--optimize-autoloader --no-dev`).

## Part B: Performance

### PHP Environment

- Latest stable PHP; enable **Opcache**; tune `realpath()` cache; no Xdebug in production.
- Optional preloading (`opcache.preloading`) — modest gains (~27.6ms → ~26.2ms on clean template);
  measure before adopting.

### Code-Level

- Watch algorithm complexity: nested loops, heavy calls inside loops.
- Cache expensive computations with `yiisoft/cache` (`getOrSet`, TTL): parsed Markdown,
  aggregated stats, config lookups.

### Sessions & Database

- Default file session storage locks per user — switch to Redis/Memcached under concurrency;
  close sessions early in actions that no longer need them.
- Index columns used in WHERE/ORDER BY (indices speed SELECT but slow writes).
- Use `LIMIT`; never fetch unbounded result sets; N+1 → eager-load/join.
- Complex reports: DB views or pre-aggregated tables + caching.

### Autoloader

```sh
composer install --optimize-autoloader --no-dev
composer dumpautoload -o
```

### Offline Processing

Resource-intensive work must not block requests:
1. **Pull**: persist tasks, process via a console command;
2. **Push**: message queue notifying a worker.

Move email sending, report generation, media processing out of the request path.

### Profiling & Measurement

Blackfire / XHProf / XDebug profiler; `yiisoft/yii-debug` panel in dev for query counts.
Measure before/after (`ab -n 1000 -c 10` or k6) — a change without a measured win is not an
optimization.

## Verification Checklists

Run after every significant change; repeat before each release. Report each item as PASS/FAIL
with file references.

**Security:** trusted proxies configured · CSRF on all mutations · cookie flags set · headers
present · debug off · errors leak nothing · AuthN/AuthR deny-by-default · argon2 hashing · uploads
validated outside public root · `composer audit` clean.

**Performance:** opcache on, Xdebug off · hot paths cached · sessions not file-locked under load ·
DB indexed + LIMIT everywhere · autoloader optimized · heavy work offline · numbers measured
before/after.
