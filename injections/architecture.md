## Yii3 support (from yii3-skills)

Load the `yii3` skill and generate or update ARCHITECTURE.md per its `references/core-architecture-alignment.md`:

Operating context: this `aif-*` workflow runs the skill in its default AI Factory extension mode (contract: `references/core-aif-adapter.md`); the standalone fallback contract (`references/core-standalone-adapter.md`) is out of scope here.

Architecture-specific duties (the rules themselves live in the skill; all `references/*.md` paths resolve relative to the `yii3` skill directory):
- Pattern & tier alignment (Step 1): map the chosen `/aif-architecture` pattern (`explicit`, `structured`, `layers`) and folder subvariants (`*-layers`, `*-vertical`, `*-flat`) to the corresponding Yii 3 isolation tier (Strict, Balanced, Pragmatic) and folder layout per `references/core-architecture-alignment.md` §1–§2 and `references/core-feature-recipes.md` §5.
- Codebase alignment & legacy policy (Step 1.5): resolve starter scaffolding (`src/Web`, `src/Api`) using the 4 strategies per `references/core-architecture-alignment.md` §3.6 (Option 1: adapt via Global Web-Shell / Quarantine; Option 2: strict target via Strangler Fig and Dedicated Main context with Anti-Dumping invariant).
- Universal presentation invariant (Step 2): enforce presentation isolation from persistence (thin actions, zero direct SQL/transactions) and composition root in `config/` per `references/core-architecture-alignment.md` §3.1–§3.3; record the chosen config organization per `references/core-config-tree.md` §2.6 and routing strategy per `references/http-routes-definition.md` §1.
- Communication & events (Step 2): define module communication in "## Layer/Module Communication" (synchronous via interfaces/public services, decoupled via PSR-14 events) and enforce the post-commit event dispatching invariant per `references/core-events-design.md` §5.
- Stack invariants & runtime safety (Step 2): record exactly one DB driver, one persistence path, one queue/cache/mutex driver, and one test runner per SKILL.md Stage 0 item 2; if RoadRunner/FrankenPHP worker runners are selected, mandate `StateResetter` lifecycle in `Key Principles` per `references/infra-state-resetter.md`.
- Idiomatic code examples & anti-patterns (Step 2): adapt template code examples to modern PHP 8.2+ Yii 3 conventions (thin Action returning PSR-7 `ResponseInterface`, DTO with `#[Required]` validator attributes, and tier-appropriate repository/service) per `references/http-actions-core.md` and `references/core-architecture-alignment.md` §6; populate "## Anti-Patterns" with Yii 3-specific violations (Yii 2 static facades `$app`, SQL in actions, service locator injection, dumping domain code in `Main`) per `references/core-definition-of-done.md` §1.
- Zero-ambiguity contract (Step 2): ensure the generated `ARCHITECTURE.md` explicitly defines concrete directory structures, module boundaries, and file naming conventions so subsequent feature plans require zero architectural guesswork.
