## Yii3 support (from yii3-skills)

Load the `yii3` skill and verify per its "Finale — Definition of Done" — the skill is the single source of gates:

Operating context: this `aif-*` workflow runs the skill in its default AI Factory extension mode (contract: `references/core-aif-adapter.md`); the standalone fallback contract (`references/core-standalone-adapter.md`) is out of scope here.

Verify-specific duties (the rules themselves live in the skill; all `references/*.md` paths resolve relative to the `yii3` skill directory):
- Code-Read-Only invariant: this workflow is strictly an independent verification gate — never modify application code (`src/`, `config/`, `migrations/`); report all defects as blockers for `/aif-fix`.
- Chain Integrity & Code-to-Reference Compliance Audit (Finale item 2, blocking): DI bindings, routes, console/event/RBAC wiring, reversible migrations, post-commit event dispatch; for every generated/modified file, audit against the Anti-Pattern Matrix of its governing guide in `references/` (thin actions, atomic use cases, isolated repositories, DTO validator attributes, PSR-15 order, constructor DI); nothing edited in `vendor/` or `config/.merge-plan.php`.
- Project checks (Finale item 1): static analysis & linters per the project's setup (Psalm/PHPStan, Rector, PHP-CS-Fixer); unknown classes, missing `declare(strict_types=1);`, or leftover legacy APIs are blocking; packages used in code must be declared in `composer.json`.
- Feature & Enterprise mode tasks: load `references/core-definition-of-done.md` (architecture & code-to-reference compliance checks, Multi-Dimensional Quality Evaluation Matrix, Production Readiness Gate, report format). File-placement judgments consult `references/core-architecture-alignment.md`: dependency-rule violation → blocking, other mismatch → `WARN [architecture-drift]`. Per the skill's Core rule 2 conflict rule: convention-only mismatches (layout, naming) are reported as drift, the code is not rewritten to match the guides.
- Zero-ambiguity handoff: append the final machine-readable fenced block with language `aif-gate-result` per the AI Factory 2.x contract (`schema_version: 1`, `gate: "verify"`, `status: "pass" | "warn" | "fail"`, `blocking: boolean`, `blockers: [{ id, severity: "error" | "warning", file, summary }]`, `affected_files`, `suggested_next: { command: "/aif-commit" | "/aif-fix" | "/aif-rules" | "/aif-architecture" | "/aif-roadmap" | null, reason }`). Populate `affected_files` with the evaluated files perimeter, identifying specific defect files in `blockers[].file`. Update the plan's `### Execution State` (`Status: COMPLETE` when blockers is empty, else `BLOCKED` with explicit entries under `Open Issues` and `Next Stage: /aif-fix`) per the AI Factory Adapter contract (`references/core-aif-adapter.md` §3).
