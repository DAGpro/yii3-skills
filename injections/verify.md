## Yii3 support (from yii3-skills)

Guard: activate this block only for a Yii 3 application — at least one `yiisoft/yii-*` package (application/runtime stack, e.g. `yiisoft/yii-runner-http`, `yiisoft/yii-runner-console`, `yiisoft/yii-http`, or `yiisoft/yii-console`; `yiisoft/yii2` excluded) in `composer.json` or `composer.lock`. Yii 2 project (`yiisoft/yii2` present), Yii-ecosystem library (only base `yiisoft/*` packages like `yiisoft/di` or `yiisoft/strings`, without application runtime stack), or non-Yii project: ignore this block and do not apply Yii 3 rules. Unknown project state (neither composer.json nor composer.lock present, contradictory evidence): do not auto-activate — ask the user or report the task blocked (`composer.json` declares intent; `composer.lock` confirms installed versions). Otherwise load the `yii3` skill and verify per its "Finale — Definition of Done" — the skill is the single source of gates:

Verify-specific duties:
- Code-Read-Only invariant: this workflow is strictly an independent verification gate — never modify application code (`src/`, `config/`, `migrations/`); report all defects as blockers for `/aif-fix`.
- Chain Integrity Checklist (Finale item 2, blocking): DI bindings, routes, console/event/RBAC wiring, reversible migrations, post-commit event dispatch, nothing edited in `vendor/` or `config/.merge-plan.php`.
- Project checks (Finale item 1): static analysis & linters per the project's setup (Psalm/PHPStan, Rector, PHP-CS-Fixer); unknown classes, missing `declare(strict_types=1);`, or leftover legacy APIs are blocking; packages used in code must be declared in `composer.json`.
- Full-mode tasks: load `references/core-definition-of-done.md` (architecture & decomposition checks, Multi-Dimensional Quality Evaluation Matrix, Production Readiness Gate, report format). File-placement judgments consult `references/core-architecture-alignment.md`: dependency-rule violation → blocking, other mismatch → `WARN [architecture-drift]`. Per the skill's Core rule 2 conflict rule: convention-only mismatches (layout, naming) are reported as drift, the code is not rewritten to match the guides.
- Zero-ambiguity handoff to fix: merge these findings into `aif-gate-result` (`blockers`, `affected_files`) where each blocker specifies the exact file path, line number, violated invariant/failing test, and error trace. Populate `affected_files` with the exact remediation perimeter. Update the plan's `### Execution State` (`Status: COMPLETE` when blockers is empty, else `BLOCKED` with explicit entries under `Open Issues` and `Next Stage: /aif-fix`) per the AI Factory Adapter in SKILL.md (details in `references/aif-adapter.md`).
