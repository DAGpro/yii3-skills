## Yii3 support (from yii3-skills)

Load the `yii3` skill (`SKILL.md`) and plan against its "Mission Workflow" section — the skill is the single source of assembly contracts, wiring gates, and dependency ordering:

Operating context: this `aif-*` workflow runs the skill in its default AI Factory extension mode (contract: `references/instructions/core-aif-adapter.md`); the standalone fallback contract (`references/instructions/core-standalone-adapter.md`) is out of scope here.

Plan-specific duties (the rules themselves live in the skill; all `references/*.md` paths resolve relative to the `yii3` skill directory):
- Archetype & package resolution (Steps 1–3): check `composer.json` against `references/package-catalog.md` and route feature archetypes via `references/INDEX.md` (pick exactly one driver per family per catalog §3; do not plan fake packages like `yiisoft/outbox` which compose from existing packages).
- Phase decomposition & pattern alignment (Step 4): decompose state-changing features into the canonical 6 plan phases aligned with the project's Architecture Pattern (`references/instructions/core-architecture-alignment.md`) and SKILL.md Mission Workflow. For surgical tasks, plan only touched components and their wiring; for composite features, preserve the full phase structure with thin actions and service/repository layers per SKILL.md. In vertical-slice architectures, enforce slice grouping: plan thin Action, DTO, and Handler tasks inside cohesive feature / use-case subfolders within the entity slice (e.g. `<Entity>/<Feature>/<Feature>Action.php`, `<Feature>Dto.php`, `<Feature>Handler.php` per `references/instructions/core-feature-recipes.md` §5 Style 1) rather than dumping all files flat into the slice root. Reject any plan that collapses this graph into 1–2 generic "create controller" tasks.
- Dependency sequencing, Upstream-First & Category A/B wiring (Step 4): order tasks bottom-up per `references/instructions/core-dependency-protocol.md` with packages installed and configured BEFORE code that uses them. For multi-context features, sequence the upstream provider context (its schema, repository, models, and public API in `src/<Module>/Api/`) before consumer contexts, strictly forbidding cross-module SQL. Differentiate Category A (auto-configured in `.merge-plan.php`) from Category B pure libraries (database drivers `yiisoft/db-*`, cache drivers, RBAC), which mandate explicit manual DI binding tasks in `config/**/di/*.php`. Every planned `*Interface` gets a DI-binding task; every Action gets an active route task in `config/**/routes.php`.
- Schema changes & post-commit events (Step 4): every schema change requires a migration task implementing `RevertibleMigrationInterface` with an explicit `down()` and table prefix `{{%table}}` (`references/packages/persistence-migrations.md`); domain events with external side-effects must be planned post-commit (after `$db->transaction()`) per `references/packages/core-events-design.md` §5.
- Zero-ambiguity task contract & Ultra Gate (Step 5): name the target file path, layer/role, and logging instructions (PSR-3 `LoggerInterface` per `references/packages/infra-logging.md` in use cases/actions, keeping domain entities pure). Every state-changing feature plan MUST explicitly schedule Phase 6 tasks (Testing & Verification Strategy per `references/packages/testing-core.md`, or a justified `N/A` if testing is externally handled) to ensure implementations do not omit tests due to plan omission. In ultra plans (the workflow's Ultra format Required Detail Gate): attach concrete signatures, DTO validator attributes (`#[Required]`), and the governing guide from `references/INDEX.md` (e.g. `Guide: references/packages/<guide-name>.md` or `references/instructions/<guide-name>.md`). Reject vague tasks lacking concrete file paths, signatures, or guide references.
- Stack invariants & clean boundary: do not plan a new folder structure or a second mechanism (ORM, router, DI style) next to the existing one per SKILL.md Stage 0 item 2. Existing-code refactoring goes strictly to "💡 Out of scope".
- Zero-ambiguity handoff (Step 6): initialize the complete `### Execution State` block template (Stage 1 pending, all wiring gates `PENDING`) at the end of the plan artifact per the AI Factory Adapter contract (`references/instructions/core-aif-adapter.md` §3) so `aif-implement` has zero missing context.
