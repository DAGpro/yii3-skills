# AGENTS.md

---

## 1. Project Overview & Identity

**yii3-skills** is an [AI Factory](https://github.com/lee-to/ai-factory) extension and multi-agent skill package designed to generate, review, audit, and refactor idiomatic code for the **Yii 3** framework (PHP 8.2+, `yiisoft/*` packages).

The repository serves as both an **AI Factory Extension** and an **Agent Skills** distribution across multiple AI environments (Cursor, Antigravity/Gemini, Devin, OpenCode, Windsurf).

> [!IMPORTANT]

> **This repository is NOT a Yii 3 application.**

> - It does NOT run Yii 3, has no application entry point (`public/index.php`), and contains no application `src/` or `vendor/`.

> - **Its sole purpose is Documentation, Rules & Knowledge Distribution:** providing structured guidelines, conventions, recipes, and workflow injections (skills, topic guides, workflow hooks, and package catalogs) for AI agents.

> - The code in `references/` (136 cloned `yiisoft/*` packages, git-ignored) is strictly an offline reference library to study and extract ground-truth signatures and patterns from.

## 2. Operating Contexts & Role of `.ai-factory/` (Authoring vs. Target Project)

Agents must clearly distinguish between two operating contexts and understand the role of `.ai-factory/` in each to prevent confusion when authoring or executing code:

### A. Authoring Context (Working Inside THIS Repository)

* **Identity:** You are the **author/maintainer of the extension**, NOT an application developer:
  - This repository (`yii3-skills`) is a meta-layer: documentation, rules, code recipes, and workflow injections for AI agents.
  - It does NOT run Yii 3 and contains no application code.
* **Role of `.ai-factory/` in THIS repository:**
  - **Internal Dev Scaffolding only:** It holds local development plans, tasks, and configurations for authoring and evolving *this* extension repository.
  - **Local & Untracked:** It is strictly excluded by `.gitignore` and is NOT part of the distributable product.
  - **Anti-Confusion Rule:** Never confuse local `.ai-factory/` scaffolding in this repository with a target application's control center. Never generate application code (`src/`, `config/web/`) in this repository. Never hardcode local dev paths into distributable skills or injections.
* **Offline Source of Truth:**
  - [PACKAGES.md](PACKAGES.md) — **navigation index over the offline library**: a concise catalog of official `yiisoft/*` packages used to decide which repositories to study for the current task. Resolve package names here first; never scan all of `references/`.
  - [references/](references/) — cloned source code of official `yiisoft/*` repositories (`src/` for signatures, `docs/` for usage examples; local clones are git-ignored).
* **Purity Invariant:**
  - Never pollute distributable skill and reference files with internal repository paths, developer-specific paths, or offline `references/` paths.
  - Maintain universal compatibility with the [Agent Skills specification](https://github.com/anthropics/skills).

### B. Target Runtime Context (When Installed in a User's Yii 3 Project)

* **Identity:** The agent is an **application developer/auditor** generating, verifying, or refactoring real Yii 3 application code in the user's project.
* **Role of `.ai-factory/` in the TARGET project:**
  - **Active Operational Control Center:** The target project's `.ai-factory/` is the supreme operational authority for the target application:
    - `.ai-factory/config.yaml` — dynamically configures project paths (`paths.architecture`, `paths.rules_file`, `paths.plans`).
    - `.ai-factory/ARCHITECTURE.md` — supreme structural authority for application architecture (Explicit, Modular, Layered).
    - `.ai-factory/rules/` — project-specific coding standards.
    - `.ai-factory/plans/` — target directory for feature plans generated by `/aif-plan`.
  - **Operational Integration (`injections/*.md`):** The extension's workflow hooks hook directly into the target project's AI Factory pipelines (`aif-plan`, `aif-implement`, `aif-verify`, `aif-fix`, `aif-review`, `aif-improve`, `aif-roadmap`, `aif-architecture`, `aif`, `aif-build-automation`, `aif-ci`, `aif-dockerize`, `aif-security-checklist`).
* **Runtime Source of Truth:**
  - Installed packages in `vendor/yiisoft/` — the API source of truth (`src/` for signatures); `composer.json` / `composer.lock` for installed versions.
  - Target project architecture, rules, and configuration. The skill's guides are the implementation instructions the project code must follow; the existing codebase layout (`src/`, `config/`) is integration context only — never a source of truth.
  - The runtime package catalog delivered with the skill: `skills/yii3/references/package-catalog.md` (**NOT** the root `PACKAGES.md`, which does not exist in target installations).

## 3. Repository Architecture & File Classification

The repository is strictly divided into **Distributable Deliverables** and **Internal Development Tooling**.

| Layer | Directories / Artifacts | Role in This Repository | Role in Target Project |
| :--- | :--- | :--- | :--- |
| **Deliverables (Product)** | Skills (`skills/`), workflow injections (`injections/`), manifests (`extension.json`) | Core product being authored and maintained | Installed and actively executed by agents (runtime package catalog: `skills/yii3/references/package-catalog.md`) |
| **Evaluation & Quality Gates** | Evals (`evals/`), quality gate scripts (`scripts/`) | Behavioral benchmark scenarios (69 test cases + `evals/runtime-harness/` L5 PHPUnit suite), ground-truth symbol and arity verification, manifest freshness checks, workflow contract tests | Not distributed to target applications |
| **Authoring References** | `references/` (`README.md`, `packages.lock.json`), `PACKAGES.md` | Offline source-of-truth metadata and package navigation index telling agents which packages to study per task | Clones and `PACKAGES.md` are not used by target agents |
| **Guidelines & Standards** | `AGENTS.md`, `README.md`, `CONTRIBUTING.md`, `CHANGELOG.md` | Developer constitution, contribution standards, and project documentation | Not distributed to end-user applications |

```text
yii3-skills/
├── skills/               # [DELIVERABLE] Agent skills directory (entry points & topic guides)
│   └── yii3/             # Canonical production skill package
│       ├── SKILL.md      # Entry point (YAML frontmatter + Task Routing Matrix + TOC)
│       └── references/   # Specialized topic guides, recipes, and runtime package-catalog.md
├── injections/           # [DELIVERABLE] AI Factory workflow hooks (plan, implement, verify...)
├── evals/                # [Internal Quality Tooling] 69 benchmark test scenarios, L5 runtime-harness, runner, and baseline metrics
├── scripts/              # [Internal Dev Tooling] Quality gates (validate.mjs, check-symbols.mjs, check-ast.mjs, check-manifest-freshness.mjs, test-aif-workflow.mjs)
├── references/           # [Authoring Only] Offline catalog metadata (README.md, packages.lock.json)

├── extension.json        # [DELIVERABLE] Extension manifest registering skills & injections

```

> [!NOTE]
> Local development scaffolding (such as dot-directories `/.*/`, local `.ai-factory/` dev plans, or offline package clones inside `references/*`) is strictly excluded via `.gitignore` and is not part of the tracked repository structure.

## 4. Extension Authoring & Synchronization Invariants

When authoring or updating skills, topic guides, and injections in this repository, agents **MUST** enforce the following engineering contracts:

### 4.1. Artifact Synchronization Cascade

Any addition or modification to topic reference guides MANDATES synchronizing dependent artifacts:

1. **Skill Entry Points (`SKILL.md`):**

   - Register the topic in the References inventory of the relevant skill (`references/INDEX.md` or `SKILL.md`) with a concise summary.

   - Add discovery keywords and trigger phrases to the YAML frontmatter `description`.

2. **Package Catalogs:**

   - **Runtime catalog (`skills/yii3/references/package-catalog.md`)** — the deliverable consulted by agents in target projects: every `yiisoft/*` package recommended by a topic guide must be present and correctly categorized there.

   - **Authoring index (`PACKAGES.md`)** — keep it accurate as an index over `references/`: when guides start covering new packages, make sure the index lists them so agents can locate the sources to study.

3. **Workflow Injections (`injections/`):**

   - If the topic introduces architectural quality gates, conventions, or verification checks, update the relevant hooks (`verify.md`, `plan.md`, `implement.md`).

4. **Manifests (`extension.json`):**

   - If a new skill directory or standalone manifest is introduced, register it in `extension.json`.

5. **Conceptual & Cross-Document Alignment:**

   - When modifying core concepts, execution models, architectural taxonomies, or API guidelines, proactively analyze and update all dependent documentation, constitution rules, skill entry points, injections, and tests. Never leave contradictory, orphaned, or stale concepts in other files.

> [!IMPORTANT]

> A task is NOT complete if dependent registries (skills, package catalogs, injections) are left out of sync.

### 4.2. Grounding & Anti-Hallucination Protocol (Mandatory Code Inspection)

Agents **MUST NOT** rely on pre-trained parametric memory, assumptions, or generic PHP knowledge when authoring Yii 3 skills, reference guides, or examples:

- **Mandatory Inspection of `references/`:** Before generating or updating any reference guide, code snippet, or DI configuration, the agent **MUST** inspect the actual package sources in `references/<package>/`:

  - `references/<package>/src/` — inspect exact class names, method signatures, parameter types, and return types.

  - `references/<package>/docs/` and `tests/` — verify idiomatic usage, configuration syntax, and architectural patterns against real tests and docs.

- **Zero Hallucination Policy:** Never invent method names, guess configuration keys, or assume Yii 2 constructs (`Yii::$app`, static facades). If an API or feature cannot be confirmed directly within `references/`, it MUST NOT be written into the documentation.

- **Automated Grounding & Static Analysis Quality Gates (`scripts/check-symbols.mjs`, `scripts/check-ast.mjs`):** All `Yiisoft\...` FQCNs, method signatures, parameter types, and call arities quoted across reference guides are statically verified against `references/` (or `evals/data/api-symbols-manifest.json` and `evals/data/ast-signatures-manifest.json` in CI). In addition, `scripts/check-ast.mjs` performs structural signature and call analysis across all PHP code blocks: validating instance calls on typed variables, static calls, fluent call chains, visibility, calling conventions, call arities, and named parameter names against declared signatures. Unconfirmed symbols or signature mismatches fail the quality gate unless explicitly allowlisted with a documented reason.

### 4.3. References Directory Safety & Search Discipline

- **Strictly Read-Only:** The `references/` directory (136 cloned packages) is strictly read-only authoring reference material. Agents must **NEVER** edit, delete, move, or stage (`git add`) any files within `references/`.

- **Targeted Search:** Never run unconstrained recursive searches across the entire `references/` folder. Resolve the relevant package names via `PACKAGES.md` first, then always target specific packages (e.g., `references/router/...`) to avoid context overflow and timeouts.

### 4.4. Language Invariant (English-Only Deliverables)

All distributable deliverables (skill entry points, topic guides, workflow hooks, and manifests) **MUST** be authored strictly in **English**, regardless of the language used in the conversation with the user.

### 4.5. Agent Skills Specification Compliance

- All skill frontmatters (`SKILL.md`) must strictly comply with the Agent Skills specification.

- The `description` field must not exceed **1024 characters** and must include explicit trigger keywords (`Use when user says "..."`).

- Internal cross-references inside skill files must use relative paths (e.g., `references/<topic>.md`) for universal cross-platform compatibility.

### 4.6. Injection Structure Contract

All workflow injections (`injections/*.md`) must follow one canonical structure so their runtime behavior is uniform across AI Factory workflows. Injections perform **no project-environment classification**: the skill applies to the extent the user's task touches Yii 3 / `yiisoft/*` packages — scope is defined by the task, never gated on project detection.

1. **Load-first opening (first content line of the body).** Every injection opens by instructing the workflow to load the `yii3` skill and defer to it, with the workflow-specific verb (e.g. "Load the `yii3` skill and verify per its ... — the skill is the single source of gates").
2. **Single source of rules.** After the opening, every injection defers to the skill ("the skill is the single source of rules") and references concrete SKILL.md / `references/` sections instead of duplicating Yii 3 rules.
3. **Structure.** Operating context (default AI Factory extension mode, contract `references/core-aif-adapter.md`; standalone fallback `references/core-standalone-adapter.md` out of scope here) → load the skill → per-workflow duties (each anchored to a skill section) → handoff/output requirements.
4. **Sync check.** `scripts/validate.mjs` verifies the structure contract: SKILL.md section references from README/injections resolve to real headings. `scripts/test-aif-workflow.mjs` verifies injection deference: every injection defers to the `yii3` skill as the single source of rules without gating on environment classification (no `Guard:` line).

### 4.7. Workflow Handoff & Artifact Contract

The Yii3 skill and the AI Factory workflows exchange results through explicit artifacts; this contract fixes the boundary between the two systems. Neither side may invent new channels or field names silently.

1. **Finale → `/aif-verify` (AI Factory 2.x `aif-gate-result` Contract).** In AI Factory mode, the skill's Finale hands control to `/aif-verify`; findings merge into the canonical AI Factory 2.x machine-readable fenced block appended as the final block of the output:
   ````markdown
   ```aif-gate-result
   {
     "schema_version": 1,
     "gate": "verify",
     "status": "pass",
     "blocking": false,
     "blockers": [],
     "affected_files": ["src/Example/ExampleAction.php"],
     "suggested_next": {
       "command": "/aif-commit",
       "reason": "Verification passed."
     }
   }
   ```
   ````
   - `schema_version`: integer (`1`).
   - `gate`: string (`"verify"`).
   - `status`: `"pass"` | `"warn"` | `"fail"`.
     - `pass`: completed cleanly without blocking defects or warnings (`blocking: false`, `blockers: []`).
     - `warn`: completed with non-blocking findings (e.g., unverified API symbols without vendor, non-blocking architecture drift, advisory notices; `blocking: false`, `blockers: []`).
     - `fail`: found at least one blocker that stops commit/merge (`blocking: true`, `blockers: [...]`).
   - `blocking`: boolean (`true` if blockers are non-empty, else `false`).
   - `blockers`: array of structured objects `[{ "id": string, "severity": "error" | "warning", "file"?: string, "summary": string }]` (blocking gate failures: Chain Integrity violations, failing project checks, packages used in code but not declared in `composer.json`). Convention-only mismatches are reported as drift warnings, never as blockers.
   - `affected_files`: array of file paths that the gate actually evaluated or cited in the result (the inspected perimeter; not limited to blocker files, but excluding unrelated repository files).
   - **Remediation Perimeter Contract (`blockers[].file` vs `affected_files`):** `blockers[].file` indicates the specific file containing an identified violation; `/aif-fix` modifies only the files necessary to resolve specific blockers within the evaluated perimeter, never touching all evaluated files blindly.
   - `suggested_next`: object `{ "command": string | null, "reason": string | null }`. Allowed commands for `verify`: `"/aif-fix"`, `"/aif-rules"`, `"/aif-architecture"`, `"/aif-roadmap"`, `"/aif-commit"`, or `null`. On pass/warn: `command: "/aif-commit"`. On failure (blocking defects): `command: "/aif-fix"`.
2. **Unverified API flag.** Any `yiisoft/*` API used without a verified installed signature (no `vendor/`, offline environment) is listed in the final report as "not verified against sources" and enters `aif-gate-result` as an advisory finding with `status: "warn"` and `blocking: false`, not a blocker — unless static analysis also fails on it.
3. **Blocked tasks.** When the skill cannot proceed safely (unknown activation state, high-impact dependency decision without a user, mandatory offline install), it reports the task `blocked` with an explicit reason instead of silently choosing; the workflow surfaces the `blocked` status as-is.
4. **Plan artifacts.** The workflow owns the plan location (`paths.plans` from the target `.ai-factory/config.yaml`); the skill never invents one in AI Factory mode. Plans follow the 6-phase decomposition contract, aligned with the Top-Down Discovery and Bottom-Up Assembly stages of SKILL.md.

### 4.8. Architecture & Workflow Contract Deference

All application execution workflows, component assembly stages, and architectural patterns are defined strictly in `SKILL.md` (and its supporting guides in `skills/yii3/references/`), which acts as the canonical single source of truth.

Agents authoring, maintaining, or modifying deliverables in this repository **MUST NOT** duplicate workflow descriptions, stage definitions, or pattern matrices inside `AGENTS.md`. All workflow invariants and execution rules defer to `SKILL.md`.

### 4.9. Mandatory Cross-File Impact Analysis & Consistency Gate

Whenever modifying contracts, reference guides, architectural rules, or core skill behaviors, agents **MUST NOT** make localized edits in isolation.

Agents MUST execute an explicit **Cross-File Impact Analysis**:
1. **Impact Discovery:** Search the codebase (`grep` / search tools) for all citations, usages, and related conceptual mentions across the repository (`AGENTS.md`, `SKILL.md`, `injections/*.md`, `skills/yii3/references/*.md`, `.ai-factory/rules/`, `README.md`, `scripts/`, `evals/`).
2. **Cascading Synchronization:** Update all referencing and dependent files in the same work unit so that conceptual shifts, deprecations, or contract changes are uniformly reflected across all layers.
3. **Zero-Drift Invariant:** A task is strictly **INCOMPLETE** if a concept or term is changed in one file while leaving stale, contradictory, or orphaned references in another. Agents must proactively verify cross-file semantic and referential consistency before concluding.
