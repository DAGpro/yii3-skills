## Yii3 support (from yii3-skills)

Load the `yii3` skill and review per it — the skill is the single source of rules:

Operating context: this `aif-*` workflow runs the skill in its default AI Factory extension mode (contract: `references/core-aif-adapter.md`); the standalone fallback contract (`references/core-standalone-adapter.md`) is out of scope here.

Review-specific duties (the rules themselves live in the skill; all `references/*.md` paths resolve relative to the `yii3` skill directory):
- Source-of-truth split: Core rule 2 — API claims checked against `vendor/yiisoft/<pkg>/src`, implementation patterns against the guides, project conventions (layout, naming) accepted as-is unless a correctness rule is violated — convention-only mismatches are reported as drift, the code is not rewritten to match the guides.
- Architectural boundary alignment (`references/core-architecture-alignment.md`): verify Presentation isolation from persistence (zero direct SQL/AR in actions, no transactions in presentation across all patterns), enforce pattern rules (Explicit domain purity, Structured module cohesion, Layered downward flow), and check the Anti-Dumping Invariant (`src/Main/` free of domain logic).
- Correctness & anti-pattern audit (Core rule 1 "Yii3 is not Yii2"): audit modified files against the Anti-Pattern Matrix of each touched topic guide (`references/INDEX.md`) — verify PSR-7/collection immutability re-assignment (`$req = $req->withAttribute(...)`), Active Record contracts (`save()` returns `void`, `delete()` returns `int`, non-static `tableName()`), thin actions returning `ResponseInterface`, and middleware order (`SessionMiddleware` before `CsrfTokenMiddleware`).
- Version-gated behavior check (`references/core-version-notes.md` R1–R24): audit deprecated or evolving APIs against installed versions in `composer.lock` (e.g. CurrentUser guest checks `$currentUser->isGuest()`, WebViewRenderer, route verb classes, middleware namespaces).
- The Chain Integrity Checklist & Multi-Dimensional Quality Matrix (`references/core-definition-of-done.md` §1–§2): verify DI bindings for new interfaces (never inject `ContainerInterface`), active routes for actions, console command registrations, post-commit event wiring (`references/core-events-design.md` §5), and require-dev isolation for tooling packages (`references/package-catalog.md` §5).
- Output severity alignment: structure findings into `Critical Issues` (merge-blocking: correctness regressions, data loss, SQL in actions, uncommitted event dispatch, auth bypass) and `Suggestions` (non-blocking: style conventions, naming drift, deprecated route syntax with working fallback), matching the `aif-review` report format and `aif-gate-result` blocker schema.
